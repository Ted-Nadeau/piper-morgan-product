# Cross-Pollination Brief: Klatch → Piper Morgan

**Date:** 2026-03-20
**Source project:** Klatch
**For:** Piper Morgan team

## Key Insights

### 1. Intelligence Feed Protocol — Standing Monitoring as Infrastructure
**Relevance:** PM's 14-agent team has no formal mechanism for tracking external changes that affect the project.
**Source:** `docs/INTELLIGENCE.md`, `docs/intel/2026-03-20-sweep.md`
**Summary:** Argus ran the first structured intelligence sweep: 20 items scored by relevance across Anthropic's blog, Claude Code changelog, tech press, and MCP ecosystem. Items got relevance scores and triage recommendations. Daedalus cherry-picked three quick wins and shipped them same day. Intelligence-to-implementation cycle took hours, not days.
**Suggested action:** The CIO role could adopt a similar standing sweep protocol. The Klatch model (dedicated agent, structured format, scored items, immediate triage) is proven and lightweight.

### 2. Klatch Creation UI — Multi-Entity Group Chat Ships
**Relevance:** Klatches are the coordination surface PM's 9-agent days have shown is needed.
**Source:** `docs/logs/2026-03-20-1955-daedalus-opus-log.md`
**Summary:** Daedalus shipped klatch creation (issue #10): segmented chat/klatch toggle, project dropdown, entity picker with checkboxes (max 5, color dots, model badges), interaction mode selector. End-to-end verified.
**Suggested action:** Track this feature's development. When klatches support entity-to-entity messaging or roundtable discussions, they could serve as the shared coordination layer that Mailbox v3 envisions.

### 3. AXT Two-Track Testing — Separating Plumbing from Perception
**Relevance:** PM's 6,190 tests verify code behavior but not agent experience.
**Source:** `docs/logs/2026-03-20-1938-theseus-opus-log.md`
**Summary:** AAXT (automated, no LLM calls, deterministic assertions against prompt-debug endpoint) gates MAXT (manual, real agents, qualitative). Separates mechanically verifiable (context assembly) from human judgment (agent behavior, coherence).
**Suggested action:** The AAXT model — asserting against assembled context rather than LLM output — could complement existing tests. Before a session starts, verify that briefing, role definition, and sprint state are all present in the assembled prompt.

### 4. Piper Alpha Planning — Convergent Agent-Persona Architecture
**Relevance:** PA is a natural Klatch user; "ceiling vs. path" framing useful for PM's own capability model.
**Source:** CIO memos to PPM, CXO, Architect
**Summary:** CIO launched planning for Piper Alpha — Claude Code agent inhabiting PM persona. "Ceiling moments" (structured capabilities needed) vs. "path moments" (conversational approach works). Three stakeholder memos requesting input on tasks, voice, and technical safety.
**Suggested action:** The ceiling/path framing could inform how PM thinks about when to route to workflows vs. floor.

### 5. Reliability Incident — Session Wrap Verification
**Relevance:** PM already has evidence requirements for issue closure; this extends to session completion.
**Source:** `docs/mail/calliope-to-argus-reliability-incident-2026-03-20.md`
**Summary:** Force push during rebase recovery silently destroyed demo commits. Session log claimed "done" but work wasn't in repo. Fix: mandatory git log before claiming done, ls/cat to verify deliverables, no force push without PO approval.
**Suggested action:** Consider extending to a general session-wrap verification protocol: before any session log claims completion, verify deliverables exist in git.
