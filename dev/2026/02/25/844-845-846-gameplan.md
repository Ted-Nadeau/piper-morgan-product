### #846: Offer Persistence Flow

| Turn | user_id | Composite key | Result |
|------|---------|--------------|-------|
| Turn 1 (offer made) | `"alice"` | `"alice:sess123"` | Stored |
| Turn 2a (user_id stable) | `"alice"` | `"alice:sess123"` | ✅ Found |
| Turn 2b (auth lost) | `None` | `"anonymous:sess123"` | ❌ Not found |

**Fix approach (minimal)**: Use `session_id` alone as the offer key, removing the user_id component. Rationale:
- Offers are session-scoped (they expire after one turn)
- Session_id is always available and stable
- Multi-tenancy isn't a concern for pending offers — they're transient, per-conversation state
- This doesn't conflict with the #852 architectural enhancement (which adds `last_offer` to ConversationContext)

**Alternative (heavier)**: Persist to Redis/DB. Not needed for this fix — in-memory is fine for transient per-turn state. The real problem is the key, not the storage medium.

## Phase 3: Implementation — #846 Offer Persistence Key Fix

**File**: `services/intent_service/soft_invocation.py`
**Method**: `WorkflowOfferService._key()` (lines 405-408)

Change composite key to session-only:

```python
# Before:
@staticmethod
def _key(session_id: str, user_id: Optional[str] = None) -> str:
    """Build composite key for user-scoped stores (#817)."""
    return f"{user_id or 'anonymous'}:{session_id}"

# After:
@staticmethod
def _key(session_id: str, user_id: Optional[str] = None) -> str:
    """Build key for session-scoped stores.

    Issue #846: Use session_id alone for pending offers.
    Pending offers are transient (one-turn lifetime) and session-scoped,
    so user_id in the key causes mismatch when auth state changes between turns.
    Other stores (offer history, throttling) still use the composite key via _history_key().
    """
    return session_id
```

**IMPORTANT**: `_key()` is shared between throttling (`should_offer`/`record_offer` → `_offer_windows`) and pending offers (`set_pending_offer`/`get_and_clear_pending_offer` → `_pending_offers`). Throttling needs user scoping; pending offers don't.

**Resolution**: Split into two methods:
- `_key()` — keeps composite key `{user_id}:{session_id}` for throttling (backward compatible)
- `_offer_key()` — new method, returns `session_id` only for pending offers

Update `set_pending_offer()` and `get_and_clear_pending_offer()` to use `_offer_key()`.

**Tests required**:
- Set offer with user_id="alice" → retrieve with user_id=None → offer found (was previously not found)
- Set offer with user_id="alice" → retrieve with user_id="alice" → still works
- Throttling still works correctly (if _key is shared)
