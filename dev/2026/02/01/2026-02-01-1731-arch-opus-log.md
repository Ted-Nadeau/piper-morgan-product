### Question 2: Multi-Intent Extension Impact

**Assessment**: SIGNIFICANT but manageable

**Current state**: `IntentClassificationResult` returns single intent. All handlers assume single intent.

**Impact analysis**:
- **Intent classifier**: Must return `List[Intent]` with confidence for each
- **Handlers**: Need batched execution capability OR orchestration layer
- **Response aggregation**: New requirement (single coherent response)

**Two architectural approaches**:

**Option A: Orchestration Layer** (RECOMMENDED)
```python
# New service handles multi-intent, handlers unchanged
class IntentOrchestrator:
    async def execute(self, intents: List[Intent]) -> AggregatedResponse:
        plan = self.create_execution_plan(intents)
        results = []
        for intent in plan.ordered_intents:
            result = await self.dispatch_single(intent)
            results.append(result)
        return self.aggregate_responses(results)
```
- Handlers stay single-intent (minimal change)
- Orchestration layer handles sequencing/aggregation
- Cleaner separation of concerns

**Option B: Handler Batching**
- Each handler accepts `List[Intent]`
- Requires touching every handler
- More invasive, higher risk

**Recommendation**: Option A. Estimated 5-8 days aligns with gap analysis. Verify #595 status first—may have foundational work.
