### Core UX Questions Addressed

1. **Lifecycle states**: User-visible states (Active, Archived) should be simpler than internal states (RATIFIED, ARCHIVED, COMPOSTED)

2. **Sidebar identity**:
   - Left = navigation ("switch to that other thing")
   - Right = entity surface (NOT just "conversation archive")
   - Critical anti-flattening: Right sidebar will surface other entity types as they harden

3. **Conversation naming**: By topic, not by state. Visual treatment shows state, name stays stable.

4. **Boundaries**: Soft close via inactivity (24-48hr), hard close via user action. New day = new conversation by default.

5. **Multi-entity compatibility**: Use "conversation owner" / "created_by" language for future multi-participant support.

### #715 Timing Recommendation

Keep in M2. Fix M0 bugs first — users aren't confused about conversation state, they're confused about whether Piper can hear them.

### Anti-Flattening Preserved

PM clarified: Right sidebar is the **entity surface**, not "conversation archive." Conversations appear first because they're the first entity type to form. Memo explicitly preserves this framing.
