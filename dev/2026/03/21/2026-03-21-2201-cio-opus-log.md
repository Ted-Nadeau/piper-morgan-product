**I-05: Piper as Software for Agents ("Agent-as-User")**
- Source: PM, Mar 21 conversation
- Date: March 21, 2026
- Concept: What if the human doesn't use Piper directly? Their preferred agent is the user — that agent negotiates with Piper M to serve the human's needs. Piper becomes a PM *service* (middleware/API) rather than a PM *assistant* (interface).
- Connections: MCP protocol (agent as client, Piper as server), Agent SDK (agents backed by processes), Klatch multi-entity model (roundtable with human's agent + Piper), PA as first "agent user" of Piper M in Phase 2
- Prior art: Existed as future concept since Piper MCP / protocol publishing discussions
- Status: Sit with it. Revisit after PA Phase 2 when we have empirical data on agent-to-agent coordination.
- Note: If this pans out, our UX work shifts from human-facing interface to agent-facing API. The structured handler architecture becomes *more* valuable in this model, not less — agents need structured APIs more than conversational ones.
