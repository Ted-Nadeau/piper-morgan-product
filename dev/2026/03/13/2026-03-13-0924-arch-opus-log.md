## PPM Memo Review

### The Problem

ProcessRegistry architecture (per ADR-049) routes messages to active workflows before intent classification. Active workflows always claim incoming messages — regardless of user intent. Result: users are trapped in workflows they can't escape.

This is a **first-impression defect** for onboarding and a trust violation for standup.

### Governing Principle

> **"The session belongs to the user, not the workflow."**

This is architecturally correct. Workflows are guests in the user's conversation. The current behavior inverts this — the workflow owns the session and the user must complete it.

### The Decisions

| Decision | Choice | Assessment |
|----------|--------|------------|
| Escape mechanism | Explicit commands + timeout now; off-topic later | ✅ Correct layering |
| Re-entry | Save state, offer once, accept no | ✅ Colleague behavior |
| Activation | Offer-first (onboarding), explicit (standup) | ✅ PDR-001 aligned |
| Standup completion | Structural + "done" signals + save partials | ✅ Natural flow |

### Architectural Assessment

**PPM's question to me**: Can these fixes be implemented within current ProcessRegistry design, or is structural change needed?

**My assessment**: The fixes CAN be implemented within the current design, but with caveats.

**What works today**:
- ProcessRegistry can check for escape keywords before routing to workflow
- Timeout can be implemented as workflow-level state check
- Offer-first activation is a handler behavior change, not architectural

**What needs attention**:
- ADR-049 specified "explicit decline patterns + timeout" as mitigation for session trapping — but this was never implemented. The architecture anticipated this problem; we just didn't build the safeguards.
- The escape keyword check should happen in ProcessRegistry, not in each workflow handler. This is a small structural change (add escape check before workflow routing) but bounded.

**Recommendation**: No ADR revision needed. Implement as specified:
1. Add escape keyword check to ProcessRegistry (before workflow routing)
2. Add timeout mechanism to workflow state management
3. Convert onboarding handler to offer-first pattern

**Scope impact**: Minimal. This is ~1-2 days of focused work per issue, not an architectural overhaul.

## Memo Response (for PPM/Lead Dev)

**Re: Architectural implications of #888/#889**

The PPM's design decisions are architecturally sound. Implementation can proceed within the current ProcessRegistry design.

**Specific guidance**:

1. **Escape keyword check**: Add to `ProcessRegistry._route_message()` BEFORE checking for active workflow. Check against canonical list: `["cancel", "exit", "stop", "skip", "never mind"]`. If matched, call `workflow.suspend()` and route to intent classification.

2. **Timeout**: Add `last_activity_at` timestamp to workflow state. Check on message receipt. If exceeded, auto-suspend and offer resume on next relevant interaction.

3. **Offer-first onboarding**: The handler's first turn becomes a yes/no question. On "no", handler returns `None` (no workflow activated) and message routes to intent classification. This is a handler behavior change, not ProcessRegistry change.

4. **ADR-049 status**: No revision needed. The architecture anticipated this problem (Section 4.2 mentions "explicit decline patterns"). We're implementing what was specified but not built.

**One structural recommendation**: Consider adding a `Workflow.can_claim(message)` method that workflows implement. Default returns `True`; escape-aware workflows check for escape patterns. This makes the pattern explicit and reusable for future workflows. Not blocking for #888/#889, but worth considering for the off-topic detection follow-on.
