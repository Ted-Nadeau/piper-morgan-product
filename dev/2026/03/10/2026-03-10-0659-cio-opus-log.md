## Innovation Item: Local Language Model for Piper

PM flagged a LinkedIn post from Julien Chaumond (Hugging Face CTO) recommending Qwen3.5-35B-A3B for local agentic work — 35B params, only 3B active (mixture of experts), runs on Apple M1 Max with 32GB RAM. Noted for reliable tool calling, stable agentic loops.

**CIO initial take (for future deep dive)**:

This is worth exploring but the use cases need to be precise. Piper currently depends on Anthropic's API for all LLM reasoning — intent classification, response generation, narrative bridge, grammar transformations. A local model wouldn't replace Claude for the core conversational intelligence (the quality gap is still real for complex reasoning). But there are several places where a fast, cheap, local model could be valuable:

- **Background processing**: Entity extraction from conversation history, pattern detection in journal entries, the "composting" pipeline where Piper processes accumulated observations. These are batch tasks where latency matters less than cost and privacy.
- **Classification and routing**: Intent pre-classification, formality detection, coreference resolution — the kind of structured extraction the KG article (from our Feb backlog) argued discriminative models handle better than generative ones. A fine-tuned local model could be faster and cheaper than API calls for these.
- **Offline capability**: If Piper ever runs as a desktop app (the DIST sprint's Phase 2), a local model provides a degraded-but-functional mode when the API is unavailable.
- **Development velocity**: Running tests against a local model instead of burning API credits for every test run. The test suite is at 6,146 — if even a fraction need LLM calls, local inference saves real money.

The Qwen3.5 MoE architecture (3B active out of 35B total) is interesting because it suggests you can get decent quality at very low compute cost. Worth benchmarking against Piper's specific classification tasks.

**Not for now** — this is a post-M1 investigation at earliest. But flagged for the CIO innovation pipeline.
