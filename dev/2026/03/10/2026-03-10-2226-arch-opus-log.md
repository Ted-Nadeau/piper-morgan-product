### 3. Infrastructure Sequencing

**Should #557 (WebSocket) come early, late, or be split?**

**Recommendation: DEFER to M2 or later.**

Rationale:
1. WebSocket is a horizontal infrastructure change that touches:
   - Frontend (new connection management)
   - Backend (new server component)
   - Deployment (new service topology)
   - Testing (new patterns needed)

2. M1's theme is "Foundation (Security + Testing)" — WebSocket doesn't fit

3. We don't have a user-facing feature in M1 that requires WebSocket. It's enabling infrastructure for future features.

4. If we must include it, **split it**:
   - M1: WebSocket server spike (proof of concept, 2-3 days)
   - M2: Full implementation with feature integration

**What depends on #557?**
- Real-time notifications (not in M1)
- Live collaboration features (not in MVP)
- Background job status (could use polling as fallback)

**What #557 depends on?**
- Nothing blocking — it's additive infrastructure
