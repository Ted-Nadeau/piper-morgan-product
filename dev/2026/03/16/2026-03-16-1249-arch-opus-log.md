## Architecture Report Review

### Key Findings

The report is strong. The routing diagram, handler classification, and design doc cross-references are thorough. The diagnosis is correct: canonical handlers are the default, floor is last resort — inverted from PDR-002 and ADR-039.

The **Action Gate** concept is the right structural answer to the "infinite exception list" problem. Instead of detecting bad responses after the fact (`_GENERIC_CANONICAL_SIGNATURES` whack-a-mole), decide before execution whether a handler is needed based on whether a side effect is required.

### Architectural Guidance Provided

- Action Gate criterion refined: "Does this intent require an operation the LLM cannot perform within the floor response?"
- Narrow fast-path exception for truly deterministic sub-millisecond responses (pure time, core identity)
- IDENTITY pushed back to canonical for core questions (consistency risk) — adjacent identity questions go to floor
- Context Assembler: keep declarative, fail gracefully, cache at assembler level
- Phase 5 addition: remove `_GENERIC_CANONICAL_SIGNATURES` entirely when inversion is complete
- Advisory questions answered: sample-based quality review, Redis caching with per-type TTLs, single model with split-ready abstraction
- Flagged that floor inversion and #888/#889 hijack fixes are both in flight touching intent routing — no conflict but Lead Dev should be aware
