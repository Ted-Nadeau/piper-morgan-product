### 2. Klatch Side Project Launched

PM spun up a new side project this morning: **Klatch** (klatch.dinp.xyz) — a Slack-inspired, local-first web app for managing Claude conversations.

**What it is**: Channel-based interface for Claude with custom system prompts per channel, persistent SQLite history, streaming responses, markdown rendering. Think private Slack workspace where every channel is a different Claude persona.

**Why it exists**: Fills the gap between claude.ai (polished but cloud-only, no data ownership), Claude Code (powerful but terminal-only), and raw API (full control but no UI). PM wants local control over models, prompts, conversation structure, and data.

**Current state**: Single channel chat, channel sidebar + creation, markdown/code blocks all working. Next: conversation management, then channel configuration and per-channel model selection.

**Long-term vision**: Unified control plane for all Claude interactions — import context from any source, define persistent roles, manage ongoing conversations across projects. Multi-entity chat (roundtable, panel, directed modes) on the roadmap.

**Tech stack**: Vite + React 19 frontend, Hono (TypeScript) backend, SQLite, SSE streaming, Tailwind CSS v4, Anthropic SDK. Monorepo via npm workspaces.

**Connection to Piper Morgan**: Built using the same methodology principles (Gall's Law, incremental working steps, architecture log recording every decision). PM's frustration with Claude interface limitations directly relates to the problems Piper Morgan also addresses — fragmented AI interaction, lack of persistent context, no customization. The multi-entity chat milestone (multiple Claude personas in one channel) connects to Piper's multi-agent coordination patterns.

**Built with**: Human (PM as product designer) + Claude writing code. Same collaborative model as Piper Morgan development.
