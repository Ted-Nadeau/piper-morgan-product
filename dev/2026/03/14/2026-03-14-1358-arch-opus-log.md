## PM Roundtable Question: "Are We Doing It Backwards?"

PM raised a concern with screenshot evidence: a user asks Piper "Can you help me manage the agents working on a coding assignment for me?" — a reasonable PM query. Piper responds: "I don't have that capability yet!" A generic ChatGPT wrapper with a one-line system prompt would have engaged thoughtfully.

PM's question: Why does Piper, after months of sophisticated development, function less well at basic communication than a wrapper? Are we building backwards?

### Architectural Assessment (~2:00 PM)

Core diagnosis: We built structured dispatch (19 intent categories → specific handlers) with a hard floor. The LLM is used to classify but not to respond when no handler matches. UNKNOWN intent → canned deflection → wall.

**Architectural framing**: The structured system should be a ceiling of enhanced capability on top of a conversational LLM floor. We built the ceiling without the floor.

**If we could change one thing tomorrow**: Replace UNKNOWN intent deflection with LLM pass-through that receives user context, project context, and conversation history. Smallest change that eliminates the "worse than nothing" failure mode.

**Memo delivered**: `memo-arch-llm-floor-roundtable-2026-03-14.md`

Risks flagged in memo: confidence boundaries (when do structured handlers fall through?), expectation management (thinking-with-you vs. doing-for-you), context quality (floor only as good as injected context), slippery slope (does a good floor undermine the case for structured handlers?).

### Roundtable Memos Received (~2:07 PM)

Read three responding memos. All four memos arrived at the same diagnosis, same principle, same immediate action independently.

| Role | Framing |
|------|---------|
| Architect (me) | LLM used to classify but not to respond — architectural inversion |
| CXO | Bouncer vs. concierge — classifier gatekeeps instead of routing |
| PPM | Layer inversion — built Layer 1 (handlers) without Layer 0 (conversation) |
| CIO | Cliff at the boundary — structured side excellent, unstructured side worse than nothing |

Unanimous agreement on principle: Piper should always be at least as good as a well-prompted LLM with the user's context. Structured handlers make it *better*, not *different*.

Unanimous agreement on immediate action: route unmatched queries to LLM with full context instead of deflection.

Unanimous agreement on what we keep: entire structured architecture stays as the ceiling.
