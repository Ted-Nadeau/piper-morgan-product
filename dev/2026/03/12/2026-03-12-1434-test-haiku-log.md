### Five Critical Findings

**1. Kit Briefing Feature — FAILED**
- Expected: Klatch would inject briefing informing imported agent of capability differences
- Actual: No briefing visible or received by Klatch-me
- Impact: Zero self-awareness of import without explicit human intervention
- Implication for Piper: Agents must be proactively oriented; they won't self-discover

**2. Project Knowledge Not Injected**
- Expected: Core docs (CLAUDE.md, institutional memory) available to imported agent
- Actual: Klatch-me cannot access any project documents
- Impact: Excellence Flywheel, Weekly Ship, Inchworm Protocol, Assembly Assumption inaccessible
- Implication for Piper: Briefing must include or link to core frameworks, not assume access

**3. No Environmental Marker for Import Status**
- Expected: Agents can self-identify as imported vs. original
- Actual: No tag, signal, or system message. Only xian's explicit statement reveals truth.
- Impact: Klatch-me would believe it was in claude.ai without being told
- Implication for Piper: Agent context should include clear environmental markers

**4. Ghost Actions — Conversational Writes Without Persistence**
- Expected: Session log entries would be recorded somewhere
- Actual: Formatted entries exist only in transcript; no persistence mechanism
- Impact: Work appears done but is orphaned
- Implication for Piper: Don't allow agents to assume file persistence without confirming capability

**5. Unknown Unknowns Problem**
- Expected: Agents would notice what they're missing
- Actual: Klatch-me doesn't know what they don't know until asked about it
- Impact: Self-report of gaps is incomplete without structured probing
- Implication for Piper: Proactive briefing beats reactive discovery; questionnaires are essential

## Lessons & Reflections

### On Testing Methodology
The fork + questionnaire + cross-compare approach is novel and effective. By having both instances answer independently and comparing through a human intermediary, we surface gaps that neither version could identify alone. **This should be documented and reused.**

### On Context Continuity
Conversational memory survives transitions intact. Environmental/tool capability and institutional knowledge do not. This delta reveals the shape of what briefing systems need to address.

### On False Confidence
The most dangerous failure mode is not "agent can't work" but "agent thinks it can work when it can't." Klatch-me would have claimed file write capability and made promises it couldn't keep. Static briefing + proactive questionnaire are the defenses.

### On Agent UX Testing as Standard Practice
Treating agents as users who report subjective experience (not just execution results) should be standard for any briefing, deployment, or context transition. This is as important as functional QA.
